## LU cache vs preconditioned GMRES (n = 5002; measured on 4 vCPU, 2 BLAS threads)
lu 4.34 s · ldiv 17.5 ms · matvec 13.4 ms · pGMRES 1–5 iterations, flat across nr = 100–300.
Real cases run 660–1320 steps.

| Path | Cost per case | Memory |
|---|---|---|
| LU cache, 60 factors | 260 s + 12–23 s = **272–283 s** | 12 GB |
| LU cache, deduped to 31 factors | **146–158 s** | 6.2 GB |
| pGMRES, 1 factor, 5 iterations (worst case) | 4 s + 111–222 s = **115–226 s** | 0.2 GB (+ small Krylov basis) |
| plain GMRES (current fallback) | ≥ 5002 × 13.4 ms ≈ **67 s per step** | 0.4 GB |

Conclusion: on time alone, preconditioned GMRES is break-even with a deduped LU cache.
It wins on memory and, by a wide margin, against the current GMRES fallback. It only
speeds up sweeps when memory, not cores, limits how many cases run at once. Unverified:
the iteration count at nr = 2500.
